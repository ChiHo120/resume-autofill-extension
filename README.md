# 简历智能填充浏览器扩展 0.6.0

Chrome / Edge Manifest V3 扩展：扫描招聘表单，调用自行配置的 OpenAI-compatible API 生成填写建议，由用户核对后填写。不会自动提交申请。

## 安装 / 更新

### 0.5.9 字段识别、状态区分与单项重试

- 优先采用关联 label、ARIA 标签和独立字段容器的文字；避免把同一行另一个输入框的标签借过来。支持开放 Shadow DOM 内的字段。
- “请输入”等无语义提示不再作为字段名称：标为“未识别字段”，只允许定位检查，不发给 AI，也不新增待补充个人信息。已识别字段缺少简历事实时才显示“资料缺失”。旧版已产生的错误建议仍可在设置页移除。
- 每项支持“生成此项计划 / 重新生成此项”和“填写此项 / 重试此项”，保留其他项的计划与执行结果。
- 页面识别拆到 `adapters/`，提供注册入口和通用实现；详见 [适配器贡献说明](adapters/README.md)。当前没有已验证的携程专用适配器。
- 下拉框仍需手动选择；关闭 Shadow DOM、跨域 iframe、未渲染控件尚不支持。测试使用合成页面与模拟模型，不代表所有招聘网站均适配。
- 新增识别回归测试：`node tests/recognition-smoke.mjs`。

### 0.5.8 暂不自动处理下拉框（当前稳定策略）

- AI 计划、AI 缺项分析和“一键填充”只接收可直接输入的文字字段：`input`、`textarea` 和 `contenteditable`。
- `select` 及常见自定义下拉框仍会被扫描并在侧栏标记，但明确显示“下拉框暂不自动填写，请手动选择”，不会展开、猜测选项或点击选项。
- 这是有意的安全降级，不是遗漏功能：招聘网站的下拉组件通常使用受控状态、虚拟列表和站点私有事件，通用自动点击容易误选。底层下拉框诊断协议保留，欢迎开源贡献者针对具体站点补充适配器。
- 代码中已注明默认流程与底层下拉框协议的边界；当前版本的可复现限制是“下拉框不自动填写，文字字段可自动填写”。

### 0.5.7 下拉框上下文诊断与完整遍历

- 扫描会遍历页面和嵌套滚动容器，记录每个下拉框的标签、所属区块、上下文文字、控件类型和实际类名。
- AI 生成计划曾尝试使用下拉框上下文和真实选项区分重复字段；该实验路径在 0.5.8 中默认关闭，状态会明确显示跳过数量。
- 填充失败时会保留下拉框未确认原因，不再用“已校验 x/x”掩盖未进入计划的下拉框。

### 0.5.6 长页面下拉框与直接填充修复

- “当前页面全部已展示表单”扫描会自动滚动整页，触发长页面的懒加载字段后再统一收集，不再只识别当前屏幕附近的下拉框。
- 增强通用下拉框识别：支持更多没有标准组件库类名的 select/Select 控件、options/option 弹层和按钮触发器；填充时重新打开下拉框、匹配实际选项并点击后校验。
- 扫描页面后，如果页面没有下拉框，可以直接点击“一键填充”；后台会自动为文字字段生成计划并执行。含下拉框的页面仍建议先点击“AI 生成计划”，确认全部下拉选项后再填充。

### 0.5.5 清理错误的待补充建议

- 设置页的 AI 待补充项可逐条“移除此项”；被移除的栏目保存在本机，后续分析不会重复加入同一栏目。
- “清除未填写建议”批量移除空白的 AI 建议，保留已填写草稿、已提交答案和自己创建的栏目。移除已提交答案时会先确认，随后更新信息汇总。
- “恢复已移除建议”清空过滤记录；再次执行 AI 分析后可重新生成这些建议。配置备份升级为 v3，保留移除记录，并兼容 v1/v2 备份。

### 0.5.4 下拉框逐项分析

- 生成计划时逐个展开可识别的单选下拉框、读取实际选项，并调用 AI 选择；侧栏显示“计划填充：本科”等具体内容，而不是选项编号。
- 可搜索的下拉框没有选项时，尝试从简历提取真实搜索词后搜索，例如学校名称；预览后恢复搜索框，不自动提交选项。
- 正式填写时重新展开并按计划中的选项名称校验，只有唯一匹配才点击；选项变化或重名时停止该项，避免误选。
- 增强相邻文字标签识别，并增加 iView、Select2、Vue Select、Naive UI 等常见单选组件的识别。
- 不支持或无法确认归属的弹层逐项给出原因，不阻断其余字段。多选、级联、日期面板、虚拟列表中未加载选项仍可能需要手动操作。

### 0.5.3 页面绑定与缺项分析修复

- 每个招聘标签页使用独立侧栏和任务状态；扫描、分析和填写固定操作原页面，切换标签页或打开设置不会把任务转移到其他网页。
- 任务在扩展后台执行。关闭并重新打开侧栏可恢复扫描、计划和进度；API 失败或后台中断后可重试，不会一直锁住按钮。浏览器重启不自动恢复未完成填写。
- 原招聘页刷新、跳转或简历资料更新时，旧计划仍会失效，避免把旧字段写入新页面。
- 缺项分析使用独立接口流程，不再被填写计划中的下拉选项值或布尔值校验阻断。
- 缺项建议自动同步为设置页中的多个输入框，另提供“刷新待补充项”和多行批量录入（每行“项目：内容”）。

### 0.5.2 补充项与信息汇总

- 用普通补充表单替换 JSON 编辑框，支持自动接收 AI 缺项建议，也可自行添加年龄、到岗时间等信息。
- 点击“提交补充并更新汇总”后，在本机将 PDF 原文、旧版简历资料和补充答案整理为可读汇总，不额外调用 AI，不猜测信息。
- 生成计划和下拉选项选择使用已提交的补充答案；同项冲突时要求模型优先采用补充值。提交更新后旧计划失效，需重新扫描生成。
- 自动保留旧版 JSON 资料，备份升级为 v2（包含补充项和待办），可导入旧版 v1 备份。

### 0.5.1 修复

- 支持仅导入 PDF 后保存配置，无需填写简历 JSON 或先进行 AI 识别；保留默认空模板也可保存。
- 支持仅 PDF 配置的备份导出和恢复，填表建议及下拉选项选择直接使用 PDF 提取文字。
- 更新设置页提示，补充仅 PDF 的保存、备份恢复和后台填表回归测试。

### 安装步骤

1. 下载项目 ZIP 并解压，或使用发布包解压目录；文件夹根目录必须有 `manifest.json`。
2. 打开 `chrome://extensions` 或 `edge://extensions`，开启开发者模式，点击“加载已解压的扩展程序”，选择该目录。
3. 更新现有扩展时，将新版覆盖到原加载目录，再点击扩展卡片的刷新按钮，关闭旧设置页并重新打开。相同加载目录一般能保留本地配置；加载另一个目录可能被当作另一个扩展。
4. 扩展使用网页访问权限读取招聘表单；浏览器可能要求重新加载扩展或重新确认权限。扫描 `chrome://`、扩展管理页和浏览器内置 PDF 页面不受支持。

## 配置 API

设置页依次填写 **API Base URL → API Key → 获取模型列表 → 选择模型**。

- 支持 HTTP、HTTPS 及带端口地址，例如 `http://example.com/v1`。HTTP 不加密传输 Key 和简历内容；建议服务支持时优先使用 HTTPS。
- 按服务商要求填写完整版本路径。若误粘贴 `/chat/completions` 或 `/models`，扩展会移除接口后缀，再追加所需接口。
- 获取模型列表调用带该 Key 的 `GET /models`，读取 `data[].id`。列表不保证每个模型均支持聊天或当前 Key 均能成功调用。
- 服务不支持模型列表时可手动填写模型 ID；手动输入优先于下拉框，重新选择下拉项会清空手动输入。
- 填写计划及 PDF 识别调用 `POST /chat/completions`。不强制发送 `response_format`，兼容未实现此参数的服务；返回 JSON 仍经过代码验证。
- 改变 API 地址会清空当前 Key，避免把旧服务密钥误发给另一个服务。
- Key 与简历仅保存在 `chrome.storage.local`，不写入源码、日志或 Git；本地存储并非加密保险库。页面脚本不能读取存储中的 Key。

## PDF 简历导入

1. 在设置页选择 PDF（可选择文字的 PDF，最多 15 MB / 30 页）。
2. 扩展使用随包附带的 PDF.js 在本地提取文字，展示可编辑预览。此阶段不向 API 上传文件。
3. 检查提取文字后可直接 **保存配置与信息**。仅 PDF 的配置同样支持导出和恢复备份；生成填表建议及选择下拉选项时会将提取文字发送到配置的 API。
4. 也可点击 **整理 PDF 信息（可选）**，由模型整理简历资料，并显示在信息汇总中。通过补充表单修正缺漏，核对后提交。旧 JSON 文件仍可导入，无需再编辑 JSON。

扫描图片型 PDF 尚未提供 OCR；完全无文字时提示先做 OCR，部分页面无文字时提示具体页码。加密、损坏或过大的 PDF 会报错，不覆盖已有简历。JSON 导入保留；`resume.example.json` 仅是虚构示例。简历 PDF 用来创建填表资料，不会自动上传到招聘网站的附件控件。

## 补充个人信息

1. 在招聘页面扫描后点击 **AI 分析缺项**，例如“建议补充【年龄】”。
2. 设置页自动出现“待补充：年龄”，已打开的设置页也会实时更新，保留当前未提交的输入。相同栏目重复分析会合并，重复经历按栏目和顺序区分。
3. 在年龄栏填写真实年龄；也可填写“其他补充项名称”后点击 **添加补充项**，添加到岗时间等信息。不确定的项目可留空。
   也可在“批量补充个人信息”中输入多行，例如“年龄：22”“期望城市：上海”，点击 **加入补充列表**，再统一提交。相同名称有多个栏目时，请在对应输入框分别填写。
4. 点击 **提交补充并更新汇总**。信息汇总展示已提交补充、PDF 原文及旧资料；按来源保留信息，同项冲突时优先使用补充值，原文不被覆盖。它与后台使用同一份保存资料，未提交的输入不会发送给 API。
5. 返回招聘页重新扫描并生成计划，再确认填写。更新资料会使旧计划失效，防止填写过时答案。

补充项可随时修改并重新提交；AI 建议可逐条移除，也可批量清除未填写建议。移除后不会再次自动出现，除非点击“恢复已移除建议”并重新分析；自行添加的栏目可移除后提交。最多 200 项，每项最多 10000 字符。只读字段、附件、同意声明不会生成自动补充任务。恢复旧版备份会恢复该备份时的资料状态。

## 填写

打开招聘表单 → 点击扩展图标 → 扫描页面 → AI 生成计划 → 逐项核对勾选 → 填充已勾选项。

- 默认全选有简历依据的可填项，并覆盖已有内容；可取消全选、逐项取消或关闭“覆盖已有值”。
- 同意/隐私条款类复选框由用户手动处理。
- 支持顶层页面标准控件、contenteditable，以及常见 ARIA/Ant Design/Semi/Element/Arco 单选下拉。iframe、Shadow DOM、多选、级联、虚拟列表滚动加载、动态新增经历、附件自动上传仍需手动处理。页面组件版本有差异，不保证所有招聘站点兼容。
- 模型输出只允许使用本次扫描的字段 ID；填写后重新读取控件值校验。导航或字段变化时需要重新扫描。
- 侧栏显示绑定页面，可点击“返回绑定页面”。切换到别的标签页时，已启动的任务继续操作原标签页；真正刷新或跳转原页面时才需要重新扫描。任务状态保留到本次浏览器会话结束。

## 开发与打包

```sh
npm ci
npm run check
npm test
npm run vendor
npm run build
```

`npm run vendor` 从锁定版本 `pdfjs-dist` 复制浏览器运行文件、CMap、标准字体和许可到 `vendor/`。这些文件已纳入仓库，下载源码即可加载，无需安装 Node。`npm run build` 输出 `dist/unpacked`，ZIP 可用 PowerShell `Compress-Archive` 生成。

浏览器测试使用 Playwright（自行安装或通过 `PLAYWRIGHT_PATH` 指定已有模块路径）及 Edge：

```sh
node tests/browser-smoke.mjs
node tests/settings-smoke.mjs
```

安装 Playwright Chromium 后，还可运行 `node tests/extension-smoke.mjs`，检查真实扩展加载及 PDF Worker 在扩展 CSP 下工作。

`node tests/workflow-smoke.mjs` 验证真实扩展的缺项同步、提交补充、信息汇总、重新生成计划并填写年龄，以及分析/填写过程中关闭侧栏、切换标签、重新打开恢复、多标签隔离和原页面导航失效。真实扩展测试也支持设置 `PLAYWRIGHT_CHANNEL=msedge` 使用已安装的 Edge；API 响应和个人资料均使用测试数据。

设置页测试实际运行 PDF.js 及 Worker，但 API 和 Chrome 权限使用模拟值，不代表真实 Key、服务商或真实招聘网站已验证。

PDF.js 6.4.299 及其许可保存在 `vendor/`；标准字体附带各自许可。`dist/`、`node_modules/`、本地密钥和私人简历不纳入版本控制。

## 0.4.0 数据保存与首次迁移

固定 manifest.key 稳定扩展 ID。不要删除或重新生成该公开身份密钥；它不是 API Key。正常刷新更新或重启保留本地 API 配置、模型、简历资料、PDF 原文件、提取文字及已提交补充项。文件选择框不会自动显示旧文件，这是浏览器行为；下方提取文字预览会恢复，填写使用最近一次保存的资料。

**从 0.3.x 首次迁移前不要卸载旧扩展。** 旧版无固定 ID，不能直接读取另一个 ID 的存储。使用单独提供的“旧版备份补丁”覆盖原来的扩展加载目录（只改设置页，不替换 manifest），刷新旧扩展，在设置页导出配置备份；再加载 0.4.0，导入备份。确认配置正确后再处理旧扩展。旧版从未保存过 PDF 原文件，迁移时如需保留原文件，请补选一次 PDF 并保存；现有 JSON 可以直接恢复，无需重新识别。

备份包含明文 API Key 和个人简历，请自己保管，不要发送给朋友或提交 GitHub。卸载扩展、清理浏览器数据、更换浏览器/用户配置仍需要导入备份；固定 ID 不代表云同步，也不能恢复已经被删除的数据。

## 0.5.0 页面对应、缺项分析与一键填写

扫描后按网页 DOM 顺序列出所有识别到的控件，而不是仅列 AI 返回的建议。范围可选“当前页面全部已展示表单（含下方内容）”或“仅当前屏幕可见区域”。未渲染/未展开的表单需展开后重新扫描。每一项均可定位网页；只读/禁用/附件/声明项显示手动原因。

“AI 分析缺项”把页面所需字段与已保存简历比较，列出建议补充的信息，不修改简历也不改网页。“AI 生成计划”基于同一份字段快照；无法确认值时标为待补充。不会根据名字猜性别或补造出生日期、证件、工作授权等事实。

计划默认勾选所有可填建议并允许覆盖。一键填充按顺序执行；单项失败继续其他项，最终复核已填值，支持停止后续操作。切换标签页、页面导航/重新加载会使计划失效。

历史下拉框实验代码仍保留用于诊断，但从 0.5.8 起产品流程不再调用；当前下拉框统一交给用户手动选择。不自动提交申请。

`node tests/dropdown-smoke.mjs` 验证底层下拉框诊断适配器（供未来站点专用实现参考）；产品工作流测试验证下拉框会被跳过、文字字段仍可生成计划并自动填写。

运行 `node tests/workflow-smoke.mjs` 验证上述流程：真实扩展及 DOM、模拟模型、虚构简历，不依赖真实 Key 或招聘账号。

## 0.6.0 计划编辑与撤销

- 侧栏支持直接编辑已生成的文字字段建议，并显示当前值与目标值。
- 下拉框继续保持手动处理，避免在填充阶段重新猜测选项。
- 每轮填写独立记录结果，停止后未执行字段不会继承上轮成功状态。
- 支持撤销最近一轮文字控件填写；若字段已被后续手动修改，则保留当前值并提示。
- 浏览器测试可运行：`npm ci`、`npx playwright install chromium`、`npm run test:browser`。
